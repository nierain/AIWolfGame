## 记下来的坑

1. **`human_game.py:1081` 是 hack**：`getattr(self.provider, "name", "") == "codex"` 就 `return False`，
   等于按 provider **名字**判断"能否同步返回决策"。新 provider 只要 `name != "codex"` 会自动绕过，
   但判断依据应该是能力位（如 `supports_inline_decision`），不是名字。
2. **换 provider 时最容易被丢掉的正是 codex-cli 的核心价值**：每次进程独立、零共享上下文，
   才换来 11 个座位推理天然分裂。改成 HTTP API 后"合并座位省 token"的诱惑会重现 2026-09-15 那次的同质化问题。
   铁律不变：一次调用 = 一个座位的 `visible_state`。
3. 成本模型相反：codex-cli 吃本机登录态（慢/耗额度），HTTP API 按 token 计费，输入 token 是大头
   （visible_state 含全场公共历史，单座位一局 20+ 次调用）→ 省钱要压 history，不是并座位。
4. 结构化输出可靠性：支持 `json_schema` 的后端才稳，小模型常返回带 markdown 围栏的 JSON，
   `_parse_output` 需要剥围栏 + 重试（现有 `--output-schema` 这层保护换后端后就没了）。

## rain 拒绝桥接模式 → 实现路线 C（HTTP API Provider）

rain 说"我不想玩桥接模式"，那就按他之前提的 API Key 走。已实现并实测。

`--api-model` / `--api-key` / `--api-base-url` / `--api-format`，新增 `启动狼人杀-API.bat`。

设计要点：
- **纯 urllib，不引入新依赖**（老模式才需要 `openai` 包）。
- 复用 `config/ai_config.json` 既有结构 `ai_players.<NAME>.{baseurl,api_key,model,timeout}`。

- **`ProviderFailure` 与 `ValueError` 必须分开**：前者是"重试也没用"（key/额度/连不上/超时）立即抛，
  后者是"输出不合法"才重试。否则 key 失效时会白转 3 次。

两个测试性能坑（都已修）：
1. `ThreadingHTTPServer.serve_forever()` 默认 poll_interval=0.5s，`shutdown()` 要等一轮 → 每个用例白等 0.5s，
   改 `poll_interval=0.02`。
2. 本机 HTTP 代理连 127.0.0.1 都拦（这就是之前 502 Bad Gateway 的来源），测试里用 `no_proxy` 绕过。
3. 完整对局的用例改成直调 `_post`（HTTP 形状已被另外三个用例覆盖），避免 250 次真实 TCP 往返。
